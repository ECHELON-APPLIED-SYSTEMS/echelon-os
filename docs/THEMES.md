# M1-C-UI: five dark themes

All five choices share the owner-approved **neutral** foundation: canvas **#191919**, sidebar **#202020**, and cards/panels **#242424**. These broad regions are never tinted by faction. Default text **#E8E8E8**, muted text **#B4B4B4**, secondary text **#D0D0D0**, hover **#2B2B2B**, controls **#2A2A2A** / **#333333**, dividers **#4A4A4A**, control borders **#919191**, error **#FFB8B2**, and positive status **#B8D8C2** are invariant too. Neutral roles have equal red/green/blue channels; the original blue bias has been removed.

| ID         | Appearance                 | Accent/highlight direction |
| ---------- | -------------------------- | -------------------------- |
| `echelon`  | ECHELON Graphite (default) | Muted teal #83C8BF         |
| `amarr`    | Amarr Empire               | Antique gold #D5B16A       |
| `caldari`  | Caldari State              | Steel blue #78ACD7         |
| `gallente` | Gallente Federation        | Emerald #63CB92            |
| `minmatar` | Minmatar Republic          | Worn copper #D78A59        |

Only `accent`, `accent-text`, `accent-wash` and `focus` vary. Highlights are confined to small brand/icon details, focus rings, selected navigation text/outline, the skip link and a restrained selected-item wash. Default buttons, surfaces, text and semantic status/error styling stay common Graphite. One `:root` base declares all shared tokens and the ECHELON fallback; each theme selector overrides exactly those four highlight tokens, never a full palette or layout.

Use **Appearance** in the sidebar; on narrow screens it stays below navigation while the legacy footer hides. The native labelled select supports browser/OS keyboard interaction and announces its selected value. Changes apply immediately across the shared shell, module placeholder, runtime/error states and controls. Navigation is preserved. Desktop selection is restored and saved by the narrow portable Rust theme API. Browser preview remains in-memory only and resets to ECHELON on a fresh load; there is no frontend local/session storage, cookie, IndexedDB or network persistence. Loading and save failure states are explicit; see [M1-D persistence](APPEARANCE_PERSISTENCE.md). Unmount restores the document's prior theme attribute, preventing test/embedding leaks.

`src/themes/themes.ts` defines exactly five typed IDs/names and safe fallback for unknown values. `themes.css` separates the shared neutral base from four-token highlight overrides, not five component layouts. `styles.css` consumes those variables throughout. The document root's `data-theme` is the styling boundary; its attributes are set by one hook from the single App state. No window synchronisation or global frontend storage service is implemented.

All palettes use `color-scheme: dark`. Tests read the actual CSS, model the actual base-plus-highlight cascade, reject extra overriding selectors, check the exact neutral colors and invariant non-highlight roles, and check distinct accent signatures, and calculate sRGB WCAG contrast: normal text/muted/status/error roles at least 4.5:1 against used surfaces, accent text on its actual surfaces, selected text and skip-link contrast, and meaningful control borders/focus outlines at least 3:1. Decorative dividers are intentionally subdued; they do not carry a state by themselves. State labels remain text, not color-only. No animation/transition was introduced, including for theme changes, so reduced-motion users receive no new motion.

Run `npm run lint`, `npm run format:check`, `npm run typecheck`, `npm test`, and `npm run build` from the repository root. Component tests cover native selector semantics/focus, all five live selections, NAVCOM continuity, honest browser preview, invalid selection, remount reset, document cleanup and absence of browser storage/network/native invocation. JSDOM cannot prove native popup behavior, real Tab order, OS focus rendering, screenreader announcements or scaling.

Browser validation for the neutral revision exercises all five accent choices at 1360px and 390px widths: selector visible, no horizontal overflow, visible focus, no network requests during swaps, reload reset, and browser preview remained unavailable for desktop IPC. ArrowDown/Enter and Tab/Shift+Tab worked in the real browser. Neutral-revision screenshots are retained locally for visual review; previous faction-tinted screenshots are historical and do not represent the current design. Those historical M1-C checks are Linux browser checks, not M1-D native persistence, screenreader or multi-DPI signoff. The Product Owner approved the neutral accent palettes before PR #4 merged; combined native rendering remains separately unverified.

The theme UI and portable foundation are merged. M1-D now adds `get_theme`/`set_theme` for the enum ID only, with strict v2 preferences and lazy, byte-preserving v1 compatibility. Appearance is restored on desktop, while workspaces still reset. The selector is disabled while loading/saving; failed loading refuses overwrite and offers retry, and failed saving clearly marks the current visible choice unsaved/session-only. Browser preview never claims persistence.

The accepted native metadata remains M1-B. Prior native baseline builds/smoke do not validate new persistence code. This task does not request another full Windows build or repeated manual smoke, and no native acceptance, merge or release is implied. Palette tokens/design, NAVCOM placeholder, CSP and remote-origin restrictions remain unchanged; only the two concrete theme command permissions are added for the local main window. No faction imagery, external assets or libraries.
